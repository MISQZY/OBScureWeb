# Ноды Transform и Style

Это модификаторы — они не имеют собственного визуального представления и начинают действовать, только будучи подключёнными *в* сокет **Transform** или **Style** ноды контента (см. [«Концепции Scene Builder»](/ru/docs/scene-builder#входные-сокеты-сгруппированы-по-роли)). Подключайте сразу несколько нод одной группы, когда нужно больше одной; при конфликте по одному и тому же полю побеждает подключённая последней.

Три из них вместо этого подключаются в собственный сокет **Layout** контейнера (Ordering) либо работают самостоятельно (Spacing/Overflow — тоже модификаторы сокета Style, просто отвечающие за box model, а не за внешний вид).

## Группа Transform

### Position  [#position]

- **Mode** — Absolute (по умолчанию) или Relative.
- **Anchor** (только в режиме absolute) — одна из 9 стандартных точек привязки (top-left, center, bottom-right, ...).
- **Offset X / Offset Y** (absolute) или **Shift X / Shift Y** (relative) — пиксели от точки привязки либо сдвиг от исходной позиции элемента.

### Size  [#size]

- **Width** / **Height** — оставьте пустым для «auto» (естественный размер элемента).

### Transform  [#transform]

- **Scale X** / **Scale Y** (по умолчанию 1), **Rotation** (градусы).

## Группа Style

### Opacity  [#opacity]

Постоянная прозрачность (0–100%), применяемая к тому, во что подключена, — устойчивое состояние, в отличие от анимации перехода у Animation's fade. Подключите и к сокету Style у Task, чтобы плавно показывать/скрывать элемент как отдельный шаг процесса.

### Shadow  [#shadow]

Тень — **Color**, **Opacity**, **Blur**, **Offset X**, **Offset Y**. Применяется как CSS-фильтр `drop-shadow` (а не обычный box-shadow), поэтому корректно повторяет обрезанный контур Shape (circle/hexagon/diamond), а не просто обрамляет его прямоугольником.

### Animation  [#animation]

- **Type** — None, Fade, Slide, Zoom или Bounce.
- **Duration** (мс).
- **Sub-type** (если Type не None) — Auto (проигрывает вход при действии Show у Task и выход при Hide), In либо Out (жёстко задаёт направление, переопределяя собственное действие Task).

### Hide  [#hide]

Ручной, статичный переключатель видимости — **Hidden**, по умолчанию включён сразу при добавлении ноды. Переключение и нажатие Save применяется сразу, без какого-либо триггера — используйте для того, что человек переключает вручную во время эфира (панель «BRB»), а **не** для чего-то по таймеру или по событию. Для элемента, который должен показываться/скрываться автоматически по алерту или как шаг процесса, используйте вместо этого действие Show/Hide у [Task](/ru/docs/scene-builder/process-nodes#task).

### Overflow  [#overflow]

Обрезает то, во что подключена, когда содержимое превышает размер блока — для этого на той же цели нужен Size (фиксированная ширина и/или высота), иначе обрезать нечего.

- **Clip X** / **Clip Y** — простое hidden/visible по каждой оси (без режима прокрутки — у Browser Source нет мыши/тача, чтобы реально пользоваться полосой прокрутки).
- **Auto-scroll** (пока только для Text) — вместо этого непрерывная зацикленная прокрутка для содержимого, которое не помещается (например, список Roulette Entrants). **Direction** (вверх/вниз/влево/вправо) задаёт ось; **Speed** — в пикселях в секунду, то есть постоянный темп чтения независимо от объёма содержимого, а не фиксированная длительность одного прохода.

### Spacing  [#spacing]

Внутренние (**Padding**) и внешние (**Margin**) отступы, подключаются в сокет Style любой ноды контента — работают одинаково для Text/Image/Video/Shape/виджетов. Каждая группа — это одно поле «задать все стороны сразу» плюс переключатель разворачивания для независимых значений **Top/Right/Bottom/Left**, в стиле Figma.

## Группа Layout

### Ordering  [#ordering]

Подключается в собственный выделенный сокет **Layout** контейнера (он есть у Shape, Group, Scene, Image, Video и у виджетов Random/Roulette), чтобы управлять расстановкой дочерних элементов:

- **Layout** — Horizontal или Vertical.
- **Direction** — Direct или Revert (меняет порядок на обратный).
- **Gap** — расстояние между дочерними элементами, в пикселях.

## Заметки

- Position/Size/Transform/Ordering подключаются одинаково независимо от того, является ли их цель элементом сцены верхнего уровня или тем, чем отдельно управляет Task в процессе, — собственные сокеты Transform/Style у Task это более узкая версия той же группировки (Style там не включает Hide/Overflow/Spacing, поскольку видимость Task — уже собственное действие Show/Hide, а Overflow/Spacing — решения только на момент построения, которые шаг процесса не может переопределить).
- Модификаторы, действующие только на момент построения (Overflow, Spacing), применяются один раз, при рендере, — их никогда нет в собственном сокете Style у Task, так что шаг процесса не может переключать их посреди последовательности.
