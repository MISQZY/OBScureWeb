# Концепции Scene Builder

Каждый оверлей в OBScure — это одна **сцена**: граф нод, который вы собираете в Scene Builder и который превращается в одну страницу Browser Source для OBS. Эта страница описывает общую модель; постраничный справочник нод — в следующих разделах ([Контент](/ru/docs/scene-builder/content-nodes), [Transform и Style](/ru/docs/scene-builder/transform-style-nodes), [Процесс](/ru/docs/scene-builder/process-nodes), [Живые данные](/ru/docs/scene-builder/live-data-nodes), [Инструменты](/ru/docs/scene-builder/tools-nodes)).

## Добавление нод и связей

Кнопка **«Добавить ноду»** открывает палитру, сгруппированную так же, как страницы справочника. Клик по группе разворачивает её, клик по ноде добавляет её на холст.

Чтобы соединить две ноды, тяните от точки на **правом** краю одной ноды к сокету на **левом** краю другой. Цвет сокета показывает, что он принимает:

- 🟢 **зелёный (content)** — Text, Image, Video, Shape, Group и другой размещаемый контент
- 🟡 **жёлтый (style)** — модификатор стиля/трансформации (Position, Size, Opacity, Animation, ...)
- 🔵 **голубой (data)** — сигнал живых данных/управления (Event, Audio Player, Variable, ...)
- 🟣 **индиго (process)** — цепочка последовательности Start→Task→Wait→End

Ничего не отрисуется, пока не станет достижимо от ноды **Scene** — единственного неудаляемого итогового узла у каждой сцены. Нода, размещённая на холсте, но никуда не подключённая, помечена подсказкой «пока не влияет на рендер».

## Два независимых вида связей

Граф одновременно несёт две не связанные друг с другом системы проводов — их стоит различать:

1. **Связи данных/композиции** («передаёт в» / «изменяет») — всё течёт слева направо к Scene. Text/Image подключаются к необязательному Shape/Group; те — к Scene; ноды-**модификаторы** (Position, Size, Animation, Hide, ...) имеют только выход, который подключается *в* то, на что они влияют, а не наоборот. Это определяет, **что существует** и как оно вложено.
2. **Связи последовательности** («затем») — цепочка `Start → Task → Wait → ... → End`, наложенная поверх структурного графа выше. Это определяет, **когда** что-то происходит. Target конкретного Task всё равно должен отдельно доходить до Scene через структурный граф, чтобы вообще отрисоваться, — одной последовательности недостаточно, чтобы что-то появилось на экране.

## Входные сокеты сгруппированы по роли

Вместо отдельного сокета под каждый тип ноды родственные модификаторы делят один сокет, сгруппированный по **роли** — по образцу стека модификаторов в Blender:

- **Transform** — принимает любую комбинацию нод Position, Size и Transform (масштаб/поворот).
- **Style** — принимает любую комбинацию нод Opacity, Shadow, Animation, Hide, Overflow и Spacing.

Оба помечены как `multi`, то есть можно подключить сразу несколько (даже две ноды одного типа). Если два провода в одной группе задают одно и то же поле, побеждает тот, что **подключён позже** — порядок приоритета можно менять пронумерованным значком, который появляется на ноде, как только за неё конкурирует несколько проводов, — та же идея, что и более поздний модификатор поверх более раннего в стеке модификаторов. Клик по значку переносит ноду в конец порядка приоритета; правый клик задаёт конкретную позицию.

## Категории нод

Цвет заголовка и левая полоса-акцент каждой ноды соответствуют одной из пяти категорий (это грубее, чем собственная группировка палитры «Добавить ноду» — несколько разделов палитры могут делить один цвет категории):

- **Process** (индиго) — Start, Task, Wait, Condition, End: цепочка последовательности.
- **Content** (изумрудный) — Scene, Text, Image, Video, Shape, Group, Random Pick и автоматически создаваемые виджеты Random/Roulette: что существует и как оно вложено.
- **Style** (жёлтый) — Position, Size, Transform, Animation, Opacity, Shadow, Hide, Overflow, Spacing, Ordering: модификаторы конкретного компонента, подключаемые в него.
- **Data** (голубой) — Event, Audio Player, Audio Source, Sound, Timer, Background FX, Clock, Variable и ноды-источники Random/Roulette: самодостаточные аксессуары и источники живых сигналов.
- **Utils** (серый) — Layout Frame, чисто визуальная рамка-группировка для организации большого графа (сверните её, чтобы прибрать холст — провода к скрытым дочерним нодам перенаправляются на край самой рамки как визуальный якорь).

## Три паттерна сцены

Сцена может их комбинировать, но чаще всего чётко попадает в один из трёх видов:

- **Статичная** — просто всегда на экране. Достаточно подключить контент прямо к Scene, без Event/Timer/процесса.
- **По событию** — [нода Event](/ru/docs/scene-builder/live-data-nodes#event) (или собственный выход Event у Audio Player/Roulette/Random), подключённая к сокету Event ноды Scene, показывает сцену при срабатывании этого алерта. Подключите к Scene ещё и [ноду Timer](/ru/docs/scene-builder/live-data-nodes#timer), чтобы задать, сколько (мс) сцена остаётся на экране до автоскрытия — без Timer используется значение по умолчанию, 6 секунд.
- **Процесс** — цепочка `Start → Task → Wait → ... → End` для пошаговой последовательности с точным таймингом и собственной анимацией на каждом шаге. Собственный сокет Event у Start выбирает, что запускает последовательность; каждый Task показывает, скрывает или обновляет ровно один компонент (подключённый к сокету Target этого Task), с собственными модификаторами Position/Size/Transform/Opacity/Shadow/Animation, накладываемыми поверх базовых модификаторов этого компонента в момент срабатывания шага. [Нода Condition](/ru/docs/scene-builder/process-nodes#condition) может разветвить последовательность надвое на основе полей самого сработавшего алерта.

## Превью, Save и Test

Панель превью редактора показывает, как сцена будет выглядеть в OBS, с учётом настроенного разрешения холста (см. [«Размер холста»](#размер-холста) ниже). Кнопка ▶ **«Играть»** проигрывает анимации и звук локально, без реального события.

**Save** и **Test** — не одно и то же:

- **Save** сохраняет граф молча — без повтора анимаций, без повтора Background FX.
- **Test** отправляет текущий граф — включая несохранённые изменения — в реальный, уже открытый Browser Source и проигрывает его вход заново, так что можно проверить вживую перед тем, как сохранять.

## Ссылка для OBS и URL-ключ

У каждой сцены есть **URL-ключ**, и адрес её Browser Source — `/overlays/<urlKey>.html` на вашем [overlay-сервере](/ru/docs/profiles-and-settings#overlay-server-address). Скопируйте ссылку из панели инструментов редактора в Browser Source OBS; она обновляется автоматически при смене URL-ключа.

## Размер холста  [#размер-холста]

Кнопка **«Размер холста»** в панели инструментов задаёт опорное разрешение, относительно которого позиционируются ноды этой сцены в редакторе и превью — она **не** управляет реальным размером/позицией Browser Source в OBS, которые настраиваются отдельно в самом OBS. По умолчанию все сцены используют общий размер холста, заданный в **Настройки → Холст**; включите «Свой размер для этой сцены», чтобы переопределить его для конкретной сцены (полезно для оверлея, рассчитанного на другое соотношение сторон, чем основной холст).

## Экспорт / импорт

Кнопки **«Экспорт схемы»** / **«Импорт схемы»** в панели инструментов сохраняют граф сцены в файл и загружают его в другом месте (другой профиль, другая машина, либо просто резервная копия перед рискованной правкой). При импорте показывается предупреждение, если файл экспортирован из другой версии приложения, — форма нод может меняться между версиями.

## Организация большого графа

Разместите **Layout Frame** (группа Utils), чтобы визуально сгруппировать несколько нод, — чисто декоративная рамка без собственных сокетов. Клик по её заголовку сворачивает её до одной строки с названием, скрывая дочерние ноды и перенаправляя любые их внешние провода на край самой рамки как визуальный якорь. Кнопка **«Упорядочить»** в панели инструментов автоматически расставляет весь граф для удобства чтения; она меняет расположение только локально в редакторе, так что после неё нажмите Save, чтобы сохранить новую раскладку.
